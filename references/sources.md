# Reference sources

How to use design galleries without producing a copy of them.

## The rule

These sites hold **other people's copyrighted work**. Consult them live, extract *principles*, never reproduce content, layouts, copy or assets wholesale. A gallery tells you how a composition breathes, what a type scale feels like at speed, where motion earns its place. It does not hand you a page to ship.

If the user asks for "a page like [specific site]", build from the underlying principle — the rhythm, the density, the motion logic — not from the surface. Name what you took: "I used the staggered reveal and the oversized numerals, not their layout."

---

## The sites

### awwwards.com
Daily curated award winners. Strongest for: ambitious motion, unusual navigation, hero concepts that are not "headline over photo."
**Extract:** composition risk, how far motion can go before it hurts usability, what "premium" currently signals.
**Watch for:** much of it is portfolio-grade, built to win awards, not to convert. Do not import that cost into a client landing page without saying so.

### cosmos.so
Visual moodboards, user-curated. Strongest for: palette and texture direction, cross-medium reference (print, photography, product).
**Extract:** color relationships, material feel, the mood vocabulary to describe a direction back to the user.
**Note:** it is a moodboard tool. Images belong to their creators. Use for direction-finding in conversation, never as assets.

### motionsites.ai
Sites indexed by their motion behavior.
**Extract:** which motion pattern fits which page section; how scroll-driven sequences are paced.

### eyecannndy.com
A glossary of motion techniques, each named and demonstrated.
**Extract:** the vocabulary. Knowing a technique is called *displacement*, *kinetic type*, or *match cut* lets you name and request it precisely. Technique names and concepts are facts, freely usable. See `motion.md`, which carries the ones worth knowing.

### ui.aceternity.com
Open-source React/Tailwind components, with source.
**Extract:** actual code, within its license. Check the license in the repo before shipping a component into client work.

## How to run a reference pass

When the user wants a direction and has no opinion yet:

1. Ask what they *like*, in any medium — a magazine, a product, a film. Faster than scrolling a gallery.
2. If they have nothing, propose two contrasting directions in words, not images. "Editorial and quiet" vs "dense and industrial." Let them react.
3. Only then open a gallery, and open it to **validate** a direction already chosen — not to browse for one. Browsing produces pastiche.
4. Bring back principles, in writing: "pages in this register run 3–4 sections, type scale jumps hard between hero and body, motion only on entry."

## Browsing live

If opening these in a browser during a session: read, extract, describe. Do not save their assets into the project, and do not paste their markup. When something is genuinely reusable it is because it is open source — and then it comes from the repo with its license, not from the rendered page.
